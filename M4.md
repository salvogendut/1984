# M4 board

The **M4** entry on the **Extensions** tab (F9 overlay) emulates the
[M4 board](https://www.cpcwiki.eu/index.php/M4_Board) — an SD-card +
ESP8266-style Wi-Fi/networking expansion sitting in upper-ROM slot 6.
With `M4ROM.ROM` paged in, BASIC sees the FAT card as a `|DRIVE`,
`cpc-sdcc` networking demos (TCPTEST, NTP, TELNET, WGET) run end-to-end
against the host's TCP/IP stack, and SymbOS-native apps (`settime.com`,
`symtel`, `wget`) talk to the network through the unmodified
`netd-m4c.exe` daemon shipped on real M4 SD cards. Backed by `src/m4.c`.

## Required ROMs

M4 is self-contained — the only ROM you need is the bundled `M4ROM.ROM`,
which the overlay loads into slot 6 automatically when you enable M4 and
pick an SD-card image. The stock BASIC and AMSDOS at slots 0/7 are kept
intact for everyday BASIC use.

| Slot | ROM         | Purpose                                          |
|-----:|-------------|--------------------------------------------------|
| 6    | `M4ROM.ROM` | M4 firmware — set up automatically by the overlay |

> The Extensions → ROM Slots menu also accepts an `m4` board tag (press
> **Ins** on a populated slot) if you want extra ROMs to load alongside
> `M4ROM.ROM` whenever M4 is enabled. Tagged ROMs are stored as
> `[board:m4]` in `1984.conf` and loaded automatically on M4 toggle.

## Compatibility with Cyboard and Albireo

M4 can coexist with the Cyboard components: Net4CPC, RTC, SYMBiFACE IDE,
and the SYMBiFACE mouse use different I/O ranges. The overlay leaves those
devices active when M4 is enabled, and board-tagged ROM profiles preserve
the slots belonging to each active board.

Albireo is the one enforced conflict. Both M4 and Albireo decode the
`0xFExx` range, and M4ROM conflicts with the Albireo/UNIDOS firmware stack.
Enabling either board disables the other, unloads only the other board's
managed ROMs, and cold-boots the CPC. Cached image paths remain available
when the board is enabled again.

## Using M4 with SymbOS

SymbOS's network daemon (`netd-m4c.exe`) runs unmodified against the M4
emulation, including from autostart. Drop a real M4 SD-card image in
via the overlay and SymbOS comes up with the daemon already running:

- `settime.com` (HTTP Time Client) — fetches the current time and
  updates the SymbOS desktop clock.
- `symtel` — connects to telnet servers (e.g. `aardwolf.org`).
- `wget` — completes HTTP downloads to the M4 FAT image.

There is one cosmetic issue: the SymbOS Sound daemon's window can pop
up on the desktop instead of staying hidden in the tray. Sound output
itself is fine — close the window and it stays out of the way.

For diagnosing future SymbOS-network issues, the `--trace-symbos-msg`
CLI flag logs every RST #10 message-send touching the network daemon
(`MSR_NET_TCPEVT` and friends) to stderr. Combined with `--trace-m4`
this gives a paired view of the daemon's SymbOS-side messages and the
corresponding M4-board commands.

## Verifying it works

### Directory metadata (issue #289)

The no-argument READDIR command retains its original formatted catalog record.
READDIR with a nonzero maximum-name-length byte returns the bounded name string
(prefixed with `>` for directories), followed by the file-size text for files.
Pathname FSTAT (`4316`) returns explicit status and, on success, size, FAT
modification date/time, attributes, the short alias and the long name. It does
not consume or restart an active directory iterator. Missing paths and malformed
non-NUL-terminated requests return errors, not empty success frames.

Image-backed metadata comes from the actual FAT entry. Directory listing and
lookup share one LFN decoder which validates sequence/checksum chains, falling
back to the real short name for malformed chains. The existing ASCII-oriented
name conversion remains; full Unicode interoperability is not claimed. Large
responses retain the existing one-byte response-length convention; the current
guest integration qualifies bounded names, not every maximum-length response.

Host-directory-backed cards use host size and modification time (DOS local-time
encoding), directory/archive attributes, the owner write bit for read-only and
a leading dot for hidden. These are host mappings, not preserved FAT metadata.
Only actual 8.3-compatible host names receive a short name; long host names have
an empty short-alias field rather than a fabricated alias. Clients needing real
DOS aliases should use a FAT image.

`make -C tests check` includes `test-m4-filesystem`, which creates private FAT16
and host-directory fixtures and sends real M4 commands through the port/ack API.
It checks old/new catalogs, full eight-character directory names, 32-bit sizes,
attributes/timestamps, long-name/short-alias lookup, malformed LFN fallback,
iterator preservation, EOF and malformed/missing-path errors. All 19 native
test executables passed for this change. An ASan/UBSan attempt could not link
because the local container lacked its referenced sanitizer runtime libraries.

The downstream GEMBENCH M4-only protocol reproducer passes unchanged, as does
its independent-directory integration (44 context checkpoints). This is an
emulator regression result, not independent confirmation on a physical M4.

### Protected image write-open (issue #291)

Image-backed OPEN checks FAT attributes before changing any cluster or directory
entry. Both replacement and OPEN_ALWAYS reject directories, volume entries and
read-only files (including case-insensitive long names and short aliases).
OPEN_ALWAYS preserves an existing writable file; append still requires an
explicit SEEK to EOF. Only a genuinely missing file may be created. Denied,
missing-parent and failed-I/O lookups no longer fall back to creation.

M4 also rejects writes to a read-only image and checks descriptor availability
before opening a file, preventing a failed dynamic open from truncating it.
Malformed and overlong joined OPEN paths are rejected rather than interpreted
as a different name. The existing FAT open wrapper uses the same checked path,
and the write routine refuses read-only handles even if a legacy caller toggles
their write-mode flag.

The native filesystem regression compares the entire private FAT16 image before
and after rejected operations, checks that descriptors are not leaked, and
exercises successful read, create, replace, empty-file and explicit append
operations. It covers fixed and dynamic descriptors, read-only device state,
failed lookup I/O and a full descriptor pool. This is not a transactional FAT
implementation: an actual I/O failure after an allowed write starts is not
rolled back. Host-directory permissions and Albireo command handling are not
qualified by this change.

All 20 native test executables and the emulator build pass. With the rebuilt
emulator, GEMBENCH's unchanged M4-only write/free-space integration passes all
45 context checkpoints (including output bytes and free-space verification),
and its directory integration passes all 44. Both boot private generated card
images through M4ROM; neither uses floppy boot or injected guest RAM. These
checks qualify the emulator integration, not a physical M4 or a full desktop.

### Interactive checks

After enabling M4 and picking an SD-card image:

1. At the BASIC prompt, type `|DRIVE` — the M4ROM extension should list
   the active drive.
2. `CAT` should list files on the FAT image.
3. From SymbOS, the network daemon (`netd-m4c.exe`) autostarts and the
   status panel switches to "Online" within a few seconds.
4. `settime.com` (HTTP Time Client) — if present in autostart — fetches
   the current time and updates the SymbOS desktop clock.
5. Run `wget` (e.g. `wget http://example.com/test.txt`) — the download
   completes and the file appears on the M4's FAT image.

If `|DRIVE` is missing from `|HELP`, M4ROM did not load. Confirm that M4 is
enabled in Extensions and that the bundled `M4ROM.ROM` can be found. The
generic Roms Board toggle is not required for M4's dedicated ROM slot.
